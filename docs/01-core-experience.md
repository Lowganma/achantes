# Achantes — Core Experience

## Experiencia principal

Achantes debe sentirse como entrar a la habitación digital del dueño de la sala.

La sala no es pública. Solo se entra mediante invitación.

El usuario no debe sentir que está entrando a una red social, sino a un espacio personal, íntimo y creativo construido por otra persona.

---

## Flujo principal del MVP

1. El dueño crea su sala.
2. Decora el canvas con imágenes, GIFs, dibujos, links y elementos visuales.
3. Agrega módulos encima del canvas.
4. Configura música de YouTube para escuchar en sincronía.
5. Copia una invitación.
6. Un invitado entra a la sala.
7. Ambos pueden escuchar música sincronizada.
8. Según permisos, el invitado puede mirar, dibujar, comentar o interactuar.
9. El dueño decide qué cambios se vuelven permanentes.

---

## Sensación deseada

La experiencia debe sentirse como:

- visitar la habitación de alguien
- explorar un collage personal
- descubrir objetos y recuerdos
- escuchar música juntos
- dibujar o dejar notas
- interactuar sin una estructura rígida

---

## Principios de interacción

## 1. El canvas es el escenario principal

El fondo/canvas debe ocupar el centro de la experiencia.

Los módulos, imágenes, notas, dibujos y elementos interactivos viven sobre ese espacio.

---

## 2. La habitación debe sentirse construida a mano

Achantes debe evitar una estética demasiado limpia o corporativa.

Debe permitir que el usuario cree caos visual, pero desde una base simple.

---

## 3. El dueño es el anfitrión

El dueño controla:

- diseño del canvas
- música
- módulos
- permisos
- guardado de cambios
- permanencia de aportes de invitados

---

## 4. El invitado entra como visitante

Un invitado puede interactuar solo si el dueño lo permite.

Los invitados con link temporal entran inicialmente como espectadores.

---

## 5. La música guía la experiencia

La música sincronizada es una parte central del MVP.

No debe sentirse como un elemento secundario.

---

## 6. La comunicación debe ser visual y textual

La sala debe permitir comunicación mediante:

- chat
- dibujos
- notas
- reacciones/emotes

No se prioriza voz o videollamada en la primera versión.

---

# Tipos de usuario

## Dueño

Usuario que posee la sala.

Puede:

- decorar el canvas
- mover elementos
- borrar elementos
- bloquear elementos
- agrupar elementos
- controlar música
- aprobar sugerencias
- modificar permisos
- guardar versiones
- aceptar o rechazar aportes temporales

---

## Invitado

Usuario invitado con permisos configurables.

Puede hacer solo lo que el dueño autorice.

Ejemplos:

- ver sala
- dibujar temporalmente
- enviar notas
- sugerir canciones
- escribir en chat
- reaccionar con emotes

---

## Espectador

Usuario que entra por link temporal sin permisos de edición.

Puede:

- ver la sala
- escuchar música sincronizada si el dueño lo permite
- leer el chat si el dueño lo permite

No puede modificar el canvas.

---

# Comportamiento esperado del canvas

## Navegación

La navegación debe ser simple:

- rueda del mouse: zoom
- rueda presionada + arrastrar: desplazamiento/pan
- botones opcionales: restablecer vista y ajustar pantalla

---

## Edición

El dueño debe poder:

- agregar imágenes
- agregar GIFs
- dibujar
- mover elementos
- superponer elementos
- ordenar por capas
- bloquear elementos
- agrupar elementos
- insertar links clickeables
- crear accesos visuales a módulos

---

## Persistencia

Los cambios hechos por el dueño son permanentes cuando decide guardar.

Los cambios hechos por invitados son temporales hasta que el dueño los apruebe.

---

# Módulos sobre el canvas

Los módulos son elementos interactivos que pueden colocarse sobre el canvas.

Para el MVP, los módulos prioritarios son:

1. Música sincronizada
2. Chat
3. Lector de PDF

Los módulos deben poder sentirse integrados visualmente al collage.

No deben parecer ventanas rígidas genéricas si se puede evitar.

---

# Definición de MVP funcional

La primera versión útil de Achantes debe permitir:

1. Crear una sala privada.
2. Decorarla visualmente.
3. Invitar a otra persona.
4. Escuchar música sincronizada desde YouTube.
5. Dibujar juntos.
6. Interactuar mediante chat.
7. Ver imágenes, GIFs y PDFs.
8. Mantener al dueño como controlador principal de la experiencia.

---

# Criterio de fracaso

El MVP fracasa si:

- la música sincronizada no funciona
- la sala no se siente personal
- el canvas se rompe con facilidad
- los invitados pueden modificar sin permiso
- Codex introduce cambios grandes sin respetar documentación
