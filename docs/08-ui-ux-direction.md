# Achantes — UI/UX Direction

## Objetivo

Definir la dirección visual y de experiencia de Achantes.

La app debe sentirse como una habitación digital personal, no como una aplicación corporativa genérica.

---

# Sensación principal

Achantes debe sentirse como:

- entrar al cuarto de alguien
- explorar un muro personal
- descubrir recuerdos
- escuchar música en compañía
- navegar un espacio íntimo, caótico y emocional

---

# Referencias visuales

Inspiraciones principales:

- MySpace
- Tumblr
- Windows XP
- MSN Messenger
- cuartos adolescentes de los 2000
- internet antiguo
- cybercafés
- anime
- juegos flash
- habitaciones desordenadas de juegos de detectives
- collages digitales ruidosos

---

# Estética base

La app debe iniciar con una base relativamente simple y vacía.

El caos debe venir de la personalización del usuario.

No debe venir de una interfaz confusa por defecto.

---

# Principio de caos controlado

Achantes debe permitir:

- superposición
- colores fuertes
- GIFs
- stickers
- dibujos
- fondos personalizados
- módulos visuales
- elementos ocultos o clickeables

Pero la navegación principal debe mantenerse usable.

---

# Lo que se debe evitar

Evitar una estética:

- corporativa
- minimalista fría
- tipo dashboard administrativo
- demasiado limpia
- demasiado rígida
- con tarjetas genéricas por todas partes

---

# Módulos visuales

Los módulos deben poder integrarse al collage.

Pueden verse como:

- posters
- reproductores personalizados
- objetos decorativos
- botones camuflados
- ventanas flotantes con estilo retro
- elementos clickeables dentro de la habitación

---

# Interacción

La experiencia debe priorizar:

- libertad visual
- exploración
- descubrimiento
- personalización
- sensación artesanal
- acompañamiento social

---

# Sonido y efectos

Sonidos de interfaz, efectos retro y animaciones nostálgicas son deseables a futuro.

No son prioridad del MVP.

---

# Responsive

La prioridad inicial es desktop.

El canvas necesita espacio amplio para funcionar correctamente.

Mobile puede quedar para fases futuras.

---

# Reglas para Codex

1. No convertir la app en dashboard corporativo.
2. No usar UI rígida si el módulo puede integrarse al canvas.
3. No romper usabilidad por estética.
4. No agregar demasiadas animaciones sin necesidad.
5. Mantener navegación clara.
6. Mantener estética personalizable.
7. Implementar cambios visuales por fases.
8. Ejecutar build después de cada fase.

---

# Criterios de aceptación

La UI cumple si:

- la sala se siente personal
- el canvas es protagonista
- los módulos parecen parte del espacio
- la estética permite caos visual
- la navegación sigue siendo clara
- la experiencia recuerda al internet personal de los 2000
